THE PROBLEM

Supervisors aren't missing. They're just hard to find fast.

Checkout is time-sensitive, and cashiers regularly hit situations they can't resolve alone:

ApprovalsRefundsReversals Price overridesDisputesPayment issues Till faultsAge-restricted salesSecurity
  • 01Cashier has to leave the till to go find a supervisor.
  • 02Calling out verbally slows the whole aisle down, not just one till.
  • 03Supervisors have no visibility of where they're needed most.
  • 04Nobody can say how long a request actually took to resolve.
  • 05Recurring problems — a faulty scanner, a slow till — go unnoticed.
THE SOLUTION

Cashier → button → alert → supervisor → resolved.

One press replaces looking, shouting, or waiting to be noticed with a structured request the whole front end can see.

01

Cashier presses the button

A button at the till, categorised by what's needed — supervisor, technical, security, or general help.

02

Till, category and time are captured

The system identifies exactly which till is calling and why, the moment the button is pressed.

03

Supervisor is alerted

A wearable, control panel, tablet or dashboard shows the till number, category and waiting time.

04

Supervisor responds

They go straight to the till that needs them — no searching, no relayed messages.

05

Request is acknowledged and closed

Every step is timestamped: requested, acknowledged, resolved.

06

Store operations data accumulates

Response times, request volumes and recurring problem tills become visible over time.

COMPETITIVE POSITION

Till buttons already exist. The platform is the differentiator.

South African providers already sell wireless till buttons and supervisor-call hardware. The opportunity for Tech Unicorns isn't the button — it's combining categorised alerts, response-time measurement, a central dashboard, store analytics and a path to POS integration into one platform.

Intellectual property focus

The IP claim sits in the specific system architecture, workflows, software and implementation methodology — not in the generic concept of pressing a button to call a supervisor. Any retailer-specific integration would sit under its own commercial and IP agreement.

DATA & SECURITY

Operational data first. No customer data required to start.

The initial system needs no customer personal information at all — just Store → Till → Alert type → Time → Response → Resolution. A production deployment would still be built around POPIA requirements: role-based access, authentication, encryption, audit logs and defined data retention.

Honest framing: everything above the fold on this page — the live demo included — is a working concept prototype built to pitch the idea. It runs entirely in this browser session and resets on reload. A production deployment would additionally require: real till hardware and a wireless gateway, a signed retailer agreement covering data and IP, POPIA sign-off from the retailer's compliance team, integration with the retailer's actual POS and store-management systems, and a hardened backend with authentication, audit logging and multi-store device management — none of which exists yet.
